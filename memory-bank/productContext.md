# Product Context — FastNote

## Why this project exists

创始需求：想要一个「笔记 + 私聊」二合一的工具，但主流 SaaS 笔记/聊天产品都要求信任服务商不窥探内容。FastNote 的目标用户对隐私极度敏感，宁愿自己承担运维自托管中继服务器的成本，也不愿意把明文数据托付给第三方。

## Problems it solves

- **笔记类工具的隐私顾虑**：云笔记服务商理论上能读取所有内容。FastNote 让笔记在离开设备前就已加密，自托管服务器物理上拿不到明文。
- **即时通讯的元数据/内容泄露**：普通 IM 依赖服务商中心化存储和解密，FastNote 采用密钥交换 + AEAD 加密，中继只转发密文信封。
- **多设备/多环境使用**：Web 版用于快速验证和跨平台访问，Electron 桌面版用于日常深度使用（同一套业务逻辑，体验一致）。
- **数据结构多样性**：既要支持自由格式笔记（Markdown WYSIWYG + 源码模式），也要支持结构化表格数据（类 Excel 的表格节点，可导入导出）。

## How it should work（用户视角的关键体验）

1. **首次使用**：设置主密码 → 本地生成/派生密钥体系 → 可选：注册云账号用于同步和聊天。
2. **日常使用**：解锁保险库（本地密码验证）→ 笔记树 + 编辑器 + （可选）聊天面板。
3. **多保险库**：一台设备可以维护多个独立的本地「保险库」（不同的加密命名空间），解锁页可切换选择要打开哪一个。
4. **云同步（可选）**：登录云账号后，笔记密文与聊天消息通过自托管中继同步/中转；不登录也能完整使用本地笔记功能。
5. **聊天**：按用户名发起 1:1 会话，支持文本 + 附件（图片预览、文件下载），未读消息在主导航和会话列表上以红点/数字提示，可配置提示音和音量。
6. **安全边界感知**：用户明确知道「忘记密码 = 数据消失」，UI 需要在关键操作处给予清晰提示，避免误操作丢数据（如二次确认删除收到的附件）。

## User experience goals

- **信任感**：任何涉及"数据去哪儿了"的功能点（同步、聊天、附件）都应该在文案/交互上体现"服务器只存密文"这个心智模型。
- **不因为加密牺牲流畅度**：解锁后应该和普通笔记应用一样顺滑（自动保存、即时搜索、平滑滚动）。
- **可定制但不复杂**：提供有限的、精心设计的主题/布局可调项（UI 主题、笔记区宽度），而不是无限自定义导致的复杂度。
- **消息通知克制且可控**：默认给出未读提示，但声音/气泡都可以在设置中关闭或调整，避免打扰。
- **清晰的破坏性操作确认**：删除收到的附件等不可逆操作，必须二次确认。
