# Project Brief — FastNote

## What it is

FastNote 是一个面向个人/小圈子使用的**隐私优先**应用，合并了两类功能：

1. **加密笔记**（类似 Notion/Obsidian 的树状笔记 + 表格）
2. **1:1 端到端加密即时通讯**

核心原则：**零知识**。服务器（自托管中继）只存储密文和无法反推明文的元数据；主密码只在客户端本地用于派生密钥，从不上传。

## Core requirements（不可妥协）

- **本地优先**：所有数据先加密存本地（IndexedDB），联网只是可选的同步/中继手段。
- **零知识服务器**：自托管的 `server/`（Fastify）只做账号鉴权、密文存储转发、WebSocket 消息中继；不持有、不可能解密任何用户内容。
- **严格密钥模式**：忘记主密码 = 数据不可恢复，不提供后门或恢复码。
- **端到端加密聊天**：聊天消息经密钥交换后加密，服务器只见密文 payload。
- **多端一致**：Web（浏览器验证/部署）与 Electron 桌面版共享同一套 `packages/*` 业务逻辑，只有壳层（渲染宿主）不同。
- **无异常外部通信**：不引入埋点/统计/崩溃上报类 SDK；所有网络请求必须经过用户自己配置的服务器地址，不允许硬编码的第三方域名。

## Scope（MVP + 已扩展）

MVP 范围见 `docs/PHASE1.md`（M1–M8 里程碑，已全部完成）。在 MVP 基础上，产品已经扩展了大量体验类功能（见 `progress.md`），包括：多本地保险库（vault）、UI 主题、聊天附件、未读提醒、笔记批量导入、可调节布局等。

## Non-goals（明确不做，除非用户后续改变主意）

- 群聊（Phase 2 预留，未实现）
- 插件/主题扩展系统（笔记编辑器层面）
- 多设备 Ratchet 状态同步优化
- 云端明文备份/恢复（严格模式下不可能实现，除非重新设计密钥体系）

## Source of truth

- 产品/协议/数据库设计的原始设计文档在 `docs/`（ARCHITECTURE.md、PROTOCOL.md、DATABASE.md、PHASE1.md）。这些文档记录的是**初始设计**，实现过程中有部分技术选型发生了演进（例如本地存储统一用 IndexedDB 而非 Electron 端的 better-sqlite3，服务端持久化用 JSON 文件存储而非直接的 SQLite 表）——以 `systemPatterns.md` 和 `techContext.md` 中记录的**当前实际实现**为准。
